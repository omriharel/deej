5. RUNNING AND MANAGING DEEJ
===============================================================================

It is a USER service, not a system service:

  systemctl --user status deej.service
  systemctl --user restart deej.service
  systemctl --user stop deej.service
  systemctl --user enable --now deej.service
  journalctl --user -u deej.service -f
  journalctl --user -u deej.service --since "10 min ago"

The launcher /usr/bin/deej:
  - creates ~/.config/deej if needed
  - copies /usr/share/deej/config.yaml to ~/.config/deej/config.yaml if the
    user config does not exist
  - changes into ~/.config/deej
  - executes /usr/lib/deej/deej

Because the binary uses config.yaml from its current working directory, the
launcher's cd is what makes ~/.config/deej/config.yaml the active config.

Package upgrades do not overwrite ~/.config/deej/config.yaml.
Removing the package does not remove ~/.config/deej either.

Uninstall:

  sudo pacman -Rns deej-git

Full manual cleanup after uninstall (only if you want it):

  rm -rf ~/.config/deej

6. KZ CASTOR / CORSAIR MIC LOOPBACK FIX
===============================================================================

Symptom:
  When system volume (especially deej master) changed, the microphone became
  audible in the KZ Castor IEMs. Sometimes it disappeared at lower volume.

Root cause:
  The Corsair VOID ELITE adapter exposes two controls with similar names:

    numid=7  Headset Playback Volume, index 0
             This is the MIC SIDETONE / loopback.
             Range 0-4096, 0 to +16 dB.

    numid=9  Headset Playback Volume, index 1
             This is the actual HEADPHONE volume.
             Range 0-55, -50 to +5 dB.

  PipeWire's ALSA mixer path picked index 0 as the KZ sink volume.
  So changing system volume was changing the mic sidetone. At 100% it set
  numid=7 to 4096 (+16 dB), which made the mic loud. At lower values it set 0,
  which is why the loopback sometimes seemed to go away.

Fix 1 - WirePlumber rule:

  File:
    ~/.config/wireplumber/wireplumber.conf.d/52-corsair-no-sidetone.conf

  Contents:
    monitor.alsa.rules = [
      {
        matches = [
          {
            device.name = "alsa_card.usb-Cosair_Corsair_VOID_ELITE_Surround_USB_Adapter_00000000-00"
          }
        ]
        actions = {
          update-props = {
            api.alsa.soft-mixer = true
          }
        }
      }
    ]

  What it does:
    PipeWire uses software volume for this card and stops writing to the
    card's ALSA mixer controls. Therefore changing volume can no longer touch
    the sidetone.

  Apply after editing:
    systemctl --user restart wireplumber

  Verify:
    pw-dump | grep -A2 api.alsa.soft-mixer
    # should show "api.alsa.soft-mixer": true

  If the USB device name ever changes, update device.name. Get the current
  name with:
    pactl list short sinks
    wpctl status
    pw-dump | grep -i corsair

Fix 2 - startup script:

  File:
    ~/.config/alsarestore.sh

  It finds the Corsair card by USB ID 1b1c:0a53, then runs:
    amixer -c <card> cset numid=7 0     # mute mic sidetone
    amixer -c <card> cset numid=5 off   # disable Auto Gain Control

  It sleeps 2 seconds first to let ALSA/PipeWire settle.
  It does NOT restore the entire ALSA state anymore.

  Original version saved as:
    ~/.config/alsarestore.sh.bak

  The old full-state file is still at:
    ~/.config/micloopoff.state

  Niri starts the script at login from:
    ~/.config/niri/config.kdl
    line: spawn-at-startup "/home/magrid/.config/alsarestore.sh"

  To run it manually now:
    ~/.config/alsarestore.sh

  There is no systemd service for it. Niri is the autostart mechanism.

Verify the fix:

  # The sidetone must be 0:
  amixer -c 4 cget numid=7

  # The real headphone volume is normally 42,42 (-8 dB):
  amixer -c 4 cget numid=9

  # Check the sink volume and default sink:
  pactl get-default-sink
  pactl get-sink-volume alsa_output.usb-Cosair_Corsair_VOID_ELITE_Surround_USB_Adapter_00000000-00.analog-stereo

  # Change the KZ sink volume and re-check numid=7. It should stay 0:
  pactl set-sink-volume alsa_output.usb-Cosair_Corsair_VOID_ELITE_Surround_USB_Adapter_00000000-00.analog-stereo 50%
  amixer -c 4 cget numid=7

  # Check whether the KZ sink is software-controlled:
  pactl list sinks | grep -A20 "KZ Castor Pro"

  With api.alsa.soft-mixer=true, the KZ sink should not use the hardware
  volume flag (HW_VOLUME_CTRL). Volume changes are applied by PipeWire in
  software.

Hardware headphone gain (optional):
  numid=9 is now fixed while PipeWire uses software volume.

    42/55 = -8 dB   (current default; loudness is safe)
    50/55 =  0 dB   (good compromise if you need more maximum volume)
    55/55 = +5 dB   (maximum; can be too loud / hiss / clip)

  Set it with:
    amixer -c 4 cset numid=9 50,50

  The script does not set numid=9. A manual change may revert after reboot
  because udev restores /var/lib/alsa/asound.state. If you want to keep a
  different value, add it to alsarestore.sh or save the ALSA state properly.

If the loopback returns:
  1. Check that the WirePlumber rule file still exists and has the correct
     device.name.
  2. systemctl --user restart wireplumber
  3. Run ~/.config/alsarestore.sh
  4. Check amixer -c 4 cget numid=7 -> values=0
  5. Check pw-dump | grep -A2 api.alsa.soft-mixer -> true
  6. If the card number changed, the script finds it by USB ID; verify with:
       for f in /proc/asound/card*/usbid; do echo "$f: $(cat "$f")"; done

8. SERIAL / ARDUINO NOTES
===============================================================================

Config currently uses:
  com_port: auto
  baud_rate: 9600

Auto mode discovers the board even if /dev/ttyUSB0 becomes /dev/ttyUSB1.
It prefers stable /dev/serial/by-id paths and reconnects when the board is
unplugged/replugged or the serial connection drops.

Optional filtering in ~/.config/deej/config.yaml:

  usb_vid: "1a86"
  usb_pid: "7523"

The current board is a CH340: 1a86:7523.

Current stable path:
  /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0 -> ../../ttyUSB0

Useful checks:
  ls -l /dev/serial/by-id/
  lsusb
  journalctl --user -u deej.service -f

If auto-detection picks the wrong device, set usb_vid/usb_pid explicitly.
If the board disappears, deej logs "Serial connection lost, will retry" and
keeps running instead of exiting.

12. ROLLBACK
===============================================================================

Mic-loopback fix rollback:
  1. Remove ~/.config/wireplumber/wireplumber.conf.d/52-corsair-no-sidetone.conf
  2. systemctl --user restart wireplumber
  3. Restore the old startup script:
       cp ~/.config/alsarestore.sh.bak ~/.config/alsarestore.sh
       chmod 755 ~/.config/alsarestore.sh
  4. Run the old script or reboot/login.

Note: the old script restores the full ALSA state from
~/.config/micloopoff.state, which may affect other cards/volumes. That is why
it was replaced with the targeted sidetone-only script.

Package rollback:
  sudo pacman -Rns deej-git

Then reinstall an older package with:
  sudo pacman -U /path/to/old/deej-git-...pkg.tar.zst
